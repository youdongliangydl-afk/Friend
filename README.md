# Friend-Pi

基于 Pi 的 macOS 开发客户端：把「一个会话」扩展成可编排的工程现场——单 Agent 直接做事，也能升起一支有任务图、有验收门禁的 Swarm；四个能力插件各自独立安装，共享同一套控制器。

**派生声明**：本项目派生自 Pi（`earendil-works/pi`）。模型执行、工具协议、认证与 JSONL 会话历史由 Pi 的公开 SDK 与 Extension API 提供，本项目不复制 Pi 的 Agent 循环，也不另存一份聊天记录。

- 固定底座：Pi `eb326d265ae0b88489a6d10319307780df827cdf`（1.0.4），锁定信息见 `pi-source.lock.json`。
- 运行时：macOS arm64、Node 24.15.0、npm 11.12.1、Electron 43.5.0。

## 1. 快速开始

### 1.1 使用交付客户端

构建产物位于 `.artifacts/mac/Friend-Pi.app`。首次打开：

1. 左下角 **设置 → 模型**：选择供应商，填入具体型号与凭证，保存后点击该型号的 **测试连接**。只有测试通过的型号才能发送消息。
2. 在 **设置 → 常规** 选择新会话默认型号与思考强度；不支持调节思考的型号会显示「不可调节」。
3. 顶栏选择一个项目（或直接用固定入口「临时会话」），在输入框里发消息。

认证文件只写入本机独立目录，界面、日志和错误信息都不展示 Key。供应商 Key 或环境变量不会自动导入整个型号目录——只有明确保存的具体型号才可用。

### 1.2 数据位置

| 内容 | 位置 |
|---|---|
| 客户端数据（设置、会话索引、`plugins.sqlite`、Swarm 工作区） | `~/Library/Application Support/Friend-Pi` |
| Pi 目录（`auth.json`、`models.json`、`sessions/*.jsonl`） | `<数据目录>/pi` |
| 临时会话默认工作目录 | `~/Documents/Friend/<会话编号>` |
| 隔离测试 | 环境变量 `FRIEND_PI_DATA_DIR` |

退出应用后整体备份数据目录与项目即可。认证文件含敏感信息，不要提交到 Git。

## 2. 界面与操作

### 2.1 顶栏、会话栏与工作台

- 顶栏横向排列项目，支持拖拽排序、边缘滚动、右键菜单左右移动，顺序会保存。
- 左栏会话列表：新建、重命名、归档、删除；左侧短线是轮次导航，支持悬停预览、书签与键盘定位。新建按钮旁的时钟切换近期/已归档。
- 右上两个镜像图标分别开关左会话栏与右工作台，分隔线可拖动或用键盘调宽，比例会保存；窄窗口按需收起会话栏。
- 工作台内切换 **文件 / Diff / Git / Swarm / Expert / Memory**，深度配置在设置。
- 工作台内容列默认占满可用宽度（最宽 1240 像素）。内容列左边缘有一条竖线，拖动或用方向键可调宽（640–2400 像素），宽度会保存；各面板不再自行限制宽度。
- 对话正文列默认 780 像素宽。正文列右边缘有一条竖线，拖动或用方向键可调宽（520–1600 像素），宽度会保存。
- 会话行右侧有「在等你」胶囊：**待确认**（权限或确认卡）、**待审核**（计划等待批准）、**待回答**（提问卡），正在执行时显示进行态。多会话并行时，先看哪一行卡在你身上。

### 2.2 对话区

- 连续的工具调用与思考折叠成一行摘要（如「执行了命令并已读取图片」），点开看输入、结果与图片；主会话与队友会话同一交互。
- 右上角显示轮次、Token、TPS；模型左侧是上下文占用圆环，悬停看比例、估算用量与容量。统计在步骤结束、模型或上下文变化时更新，冷启动从原生历史恢复。
- **对话 / 轨迹** 两个页签：轨迹按原始消息与系统记录展开模型身份、用量、耗时、工具输入输出、错误与中断；三轮道视图可在等宽与真实耗时之间切换。每轮结束会附本轮文件变更摘要，点开进入该轮的 Diff。
- 运行中按 `Enter` 把消息排入队列：可编辑、删除、转成侧聊草稿；「关闭排队」暂停自动发送，「恢复排队」继续。停止或重启后队列保留，发送结果不明确时显示待确认，不会自动重发。队列项上的「引导」等同 `⌘ Enter`，把这条消息直接发送到当前执行。

### 2.3 输入区

- 输入区工具栏保持精简：「+」菜单里放**文件和文件夹**、**目标**、**先规划**；右侧是执行方（个体 / 团队 / 组织）、权限档位与模型。执行方控件默认只显示图标，只有当前选中的那一项展开并显示文字。计划模式开启时，「+」旁显示「先规划」状态，点它退出计划模式。
- 计划模式使用只读探索工具，产出计划并提交版本；只有正式提交的计划会出现审批卡，批准绑定该版本，要求修改会让旧批准失效。
- Goal 是可选的长目标（入口在「+」菜单）：会话级保存，安静推进，暂停/恢复/清除只能由用户操作，模型只能记录状态。
- 附件：文本与图片，图片需当前模型支持；单个附件上限 10 MiB、合计 20 MiB，消息与附件说明的文本总量上限 128 KiB。
- 权限档位常驻在输入框左下角：每次询问 / 安全自动 / 所有权限；未显式选择时沿用新会话默认权限策略（悬停按钮可见），执行中或归档时说明为什么不能切换。
- 右侧只保留一个随状态变化的按钮：空闲时是纸飞机（发送），执行中且输入框为空时是红色圆圈（终止当前任务），执行中且输入框有文字时回到纸飞机（点击等同 `Enter`，按排队处理）。
- 流式执行中：`Enter` 把消息排进队列（可编辑、可删除）、`⌘ Enter` 追加到当前回合（followUp）、`⌘ ⇧ Enter` 立即插入纠偏（steer）。
- 快捷键：`Enter` 发送，`Shift Enter` 换行（输入法确认候选不会发送），空闲时 `⌘ Enter` 也是发送、执行中是追加到当前回合，`⌘ N` 新会话，`⌘ K` 命令面板，`⌘ F` 搜索项目与会话，`Ctrl` + 反引号打开终端。

### 2.4 文件工作台与 Diff

- 按需展开的目录树、多文件标签、CodeMirror 编辑、`⌘S` 保存；外部改动时确认重载或覆盖，未保存关闭可选保存/放弃/取消。
- Markdown 本地图与相对链接、图片、隔离 HTML 可预览；大文本按 256 KiB 分段只读，其他类型交给系统打开。
- Diff 支持行内/双栏、工作区/未暂存/已暂存/本轮期间四种口径；本轮基线失效会明确提示，而不是显示成零变更。

### 2.5 内嵌终端

- 顶栏按钮或 `Ctrl` + 反引号打开；底部、右侧、应用内浮窗三种停靠，多标签、尺寸与位置可恢复。
- Agent 服务终端的**首次用户输入会接管**：键入、粘贴或输入法实际输入才算接管，读取/滚动/改尺寸不算；交还后恢复 Agent 控制。
- 隐藏面板保留进程，标签关闭停止所属进程，退出应用停止全部终端；重启只恢复记录，不重放命令。

### 2.6 Git 面板

- 顶栏工具栏或命令面板打开 Git 页：分支与 HEAD、脏文件列表（`M`/`A`/`D`/冲突字母）、逐文件 diff、暂存 / 取消暂存、提交框与最近提交历史。
- 所有操作在项目工作区内以 argv 形式调用系统 git，不拼接命令字符串；非 Git 目录、无权限和冲突都会给出中文原因，不会静默失败。
- 安全边界：提交时禁用仓库钩子（`core.hooksPath` 指向空），依赖 pre-commit 的流程请在终端提交；单文件差异上限 256 KiB、状态列表 500 项、历史 200 条，超限会明说已截断。
- 本轮不实现 fetch / push / 分支切换、冲突解决与回滚；需要时仍走终端。

### 2.7 命令面板

- `⌘ K` 打开，输入即过滤：面板（会话、网页、文件、Diff、Git、终端、任务、Expert、Memory）、设置分组、会话动作（新建、搜索、重命名、停止、归档/恢复）。
- `↑`/`↓` 选择、`Enter` 执行、`Esc` 关闭；不可用项灰显且不会被回车执行。面板打开时其它快捷键不会穿透。

## 3. 四项能力

四个能力都是可独立安装的 Pi Package，互不依赖：关掉任意一个，其余照常工作。GUI、`friend_*` 模型工具和斜杠命令进入同一个控制器；模型不能替用户批准管理动作。

| Package | 面向用户的能力 | 落盘的业务记录 |
|---|---|---|
| `@friend-pi/swarm` | 任务图、成员、消息、共享材料、独立复核 | DAG、尝试、收据、工作区、检查与复核记录 |
| `@friend-pi/expert` | 可配置专家、按次覆盖、版本冻结、方法成长 | 不可变版本、内容摘要、采用记录、限域验证结果 |
| `@friend-pi/memory` | 搜索、来源、纠正、停用、遗忘、后台学习 | 七类记忆、来源版本、抑制与审计记录 |
| `@friend-pi/topic-rebuild` | 自动/手动整理、工作现场、历史回查 | 来源覆盖、水位、现场版本、可重建索引 |

安装到已有 Pi（注意 Pi 不会自动解包 `.tgz`）：

```sh
mkdir -p /absolute/path/plugins/swarm
tar -xzf .artifacts/packages/friend-pi-swarm-*.tgz -C /absolute/path/plugins/swarm
pi install /absolute/path/plugins/swarm/package
```

也可以直接用 `.artifacts/packages/unpacked/<插件>/package` 绝对路径，或用 `pi -e <插件>/dist/index.js` 临时加载。Pi 与 TypeBox 是 peer 依赖，包里不带第二份 Pi。

### 3.1 Swarm

**基本形态**：给出目标，拆成有依赖的任务图，成员并发执行，客观检查 + 独立复核通过后才允许整合。默认并发 4、上限 16、累计最多 64 个逻辑节点。五个内建角色是模板，角色目录可搜索、分页、自定义。

**执行策略（新图冻结）**：`workspace: isolated | shared`、`review: required | none`、`dirtyBaseline: snapshot | reject`。旧图按原策略恢复；策略在尝试中途不可改。

- 隔离模式用受管快照执行，只回写本次任务增量，应用前核对目标内容；共享模式直接使用当前项目，成员不自行提交或切换分支。
- 脏基线快照保留用户原有暂存/未暂存/未跟踪内容；整合只应用任务增量。
- 复核选择「无」时，交付明确标注「未进行独立复核」；用户要求的复核不能被下游放行。

**协作 v2 平面（`v2.*`，附加于既有 DAG 平面）**：

- 任务板 8 态 + 墓碑、连续 revision / CAS、DAG 校验、写范围重叠拒绝、256 个活跃任务上限。
- 确定性调度：按依赖深度 → 创建时间的 ready 前沿派发；写声明 preflight 返回 `Held{Cause,By}`，被挡任务跳过，其他独立任务继续。
- 三层预算（team / task / member 的 token、cost、time、并发）：reserve 冻结上界，settle 按原生 receipt 结算，unknown 不冒充已知；耗尽即停止派发，但不宣称硬截断在途请求。
- 验证与合并门禁：检查注册表（`file.exists` / `file.hash` / `json.schema` / `source.coverage` / `command.exit`）、V0–V3 强度、结构化封存裁决、reviewer 独立性、exact-tip 绑定、返工配额与失败指纹；`v2.integrate` 必须通过 G01–G20，无裁决只产生 rejected 回执。
- 消息四态（accepted / queued / delivered / incorporated）、每目标 FIFO、幂等、`wait` 只观察调用之后的变化。
- 权威是 append-only journal，当前态表是同事务物化快照，投影可整体重建；首次建表前 `VACUUM INTO` 备份。设置 `FRIEND_PI_SWARM_V2=0` 可关闭。

**边界**：v2 的 `integrate` 记录逐文件回执、门禁与审计，不直接写文件系统；真实文件应用与回滚仍由既有隔离/应用平面完成。工作树是协作隔离，不是 OS 沙箱。

### 3.2 Expert

- 统一配置提示词、Skill 列表、工具集合、模型与可选思考等级；支持新增、编辑、复制、启停。保存启用后即可选用。
- 派生前按 **本次覆盖 → 预设 → 宿主默认** 解析：显式 Skill / 工具列表**替换**预设；`toolsMode: inherit` 用可用集合，`allowlist` 且 `tools: []` 表示不开放任何模型工具；有效工具始终被宿主与任务权限收紧。
- 派生前冻结实际提示词、Skill 正文与版本、工具和模型；后续编辑不影响已运行成员。无效模型/工具/Skill 明确报错，不会悄悄退回基础角色。
- 内建 5 个专家是模板，不限制角色数量。自动方法成长（真实 SDK 验证 + 隐藏发布，≥36 个任务、≤64 次 provider 请求）保留为独立高级流程，不影响手动配置直接可用。

### 3.3 Memory

**七类记忆**：`profile` / `preference` / `fact` / `experience` / `episode` / `task` / `knowledge`。每类有自己的范围、权威、TTL、复审周期与置顶资格；旧 `method` 记录只读保留，不参与召回。

**写入**：项目经验与个人偏好自动学习；明确、有来源的经验原子发布，歧义保持候选。自动发布受四档策略（`off` / `conservative` / `standard` / `aggressive`）与十道确定性门禁约束，每次判定写审计并可回滚；连续纠正或回滚会触发自动降档。用户显式「记住」直接生效；附件、引用指令、临时 Goal 与模型自评不能取得用户权威。

**读取**：FTS5/BM25 + CJK 二元分词，无向量库、无 reranker、无查询改写模型。排序按精确 ID/标题/别名/错误码/路径优先，再叠加主体、BM25、任务上下文、反馈、范围、信任与时间衰减，冲突 −3、过期 −2、重复 −1；`search.explain` 给出每个特征的贡献与理由。三级预算：置顶 ≤1500 字符（独立）、目录 ≤1500、正文 ≤3500（正文与完整条件一起放下，否则保留精确只读指针），一次 6 条、硬上限 8，最多两条明确适用的偏好优先。

**生命周期**：到期记录不进召回；复审队列覆盖到期、低用量、负反馈、抽样、冲突与来源失效；Dream v2 做确定性巩固（合并、归档、关系、拆分、画像、蒸馏），写审计并可回滚；遗忘保留墓碑与抑制信息，防止冷启动重新学到同一错误。

**注入回执**：Memory 页签显示「本轮记忆」——一行汇总正文注入 / 目录 / 未用与正文预算，条目一行一条；展开可看完整正文、适用条件、来源与摘要，阶段链与多轮明细收在「完整回执」里。回执只证明记录被送入上下文或请求，不证明模型采用，也不证明答案正确。

**Memory Center**：设置 → 记忆 → 打开记忆中心，九个页签——概览 / 记录 / 候选 / 冲突 / 复审 / 学习 / 图谱 / 用量诊断 / 设置。记录页默认一行一条（标题、一句摘要、类型 / 范围），版本、来源、条件与动作在右侧抽屉按需出现；批量操作与「记住一条」也在记录页。候选永远不显示为生效；破坏性操作先给影响摘要并要求确认。

**权威与导出**：SQLite 是权威，`memory-views/` 下的 Markdown 是只读派生视图，可重建、不反向导入。设置 → 记忆只保留启用开关、自动学习状态、记忆中心入口与导出；浏览、搜索与治理都在记忆中心完成。

### 3.4 Topic & ReBuild

- 默认使用 Pi 原生压缩，不替换其触发与保存流程；只有打开「无限上下文」时，压缩才结合有效历史记忆生成保留片段与摘要。后台只准备草稿，前台压缩钩子校验并采用。
- Pi JSONL 是原始历史的唯一来源。工作现场绑定原文 ID 与覆盖范围，**只在 Pi 真正保存检查点或压缩条目后**推进水位。
- 原任务目标与本轮请求分开保存：追问「进度怎么样」不会覆盖目标，只有明确换任务才替换。
- 长条目按有界区间选材并记录未覆盖范围；时间线展示目标、决定、冲突、来源与采用状态。
- 记忆纠正或遗忘会让相关派生现场失效，下一安全边界重建；失败、取消或预算不足时保留旧现场并退回原生压缩。

### 3.5 能力中心

设置 → 扩展里的能力中心把四类能力放进同一页：**Skills / Plugins / MCP / Slash**。每一项显示三态——已配置、已加载、当前会话可用——失败的条目标红并给出具体原因；没有数据源的类别显示真实空态，不用占位数据填充。

## 4. 模型与供应商

预置 DeepSeek、OpenAI、Anthropic、Google Gemini、Moonshot/Kimi、MiniMax、阿里云百炼、智谱、火山方舟；选择厂商后自动预填公开地址、协议与默认型号，Key 只进入 Pi 私有认证存储。

每个型号单独测试连接：成功后状态与该型号、地址、协议和认证摘要绑定；改动同供应商配置会让已通过状态失效，需要重测。自定义型号使用保守容量（上下文 32768、输出 4096），不描述成厂商上限。前台、插件调用、Swarm 成员与后台学习使用同一校验规则。

## 5. 架构

```text
Electron / React 客户端
└─ Preload 与 Main：原生窗口、文件交互、请求路由
   └─ 独立 Node Pi SDK 会话进程
      ├─ Pi 模型、工具、认证、JSONL 会话与原生压缩
      ├─ 四插件控制器与版本化请求／事件
      └─ Swarm 独立成员 Node 进程与工作区
```

- 每个插件是独立 Pi Package，通过版本化事件总线请求通信，不共享模块单例，不 import 彼此控制器。
- 插件开关在会话空闲后执行真实 reload 并重绑交互；任务结束依据会话结算事件与协作调度状态。
- SQLite 只存业务数据、会话路径与索引，不另存聊天正文。

### 5.1 执行后端

会话进程有两种执行后端，由环境变量 `FRIEND_PI_EXEC` 选择，默认 `pi`：

| 取值 | 后端 | 会话历史 | 状态 |
|---|---|---|---|
| `pi`（默认） | Pi 编码 Agent | JSONL，位于 `sessions/` | 稳定，日常使用 |
| `durable` | Pi Durable Harness | 每会话一个 SQLite，位于 `durable/` | 实验性，见「边界与未完成」 |

未知取值会直接报错而不是回退到默认值，避免写错的开关被当成切换成功。

`durable` 后端复用同一套 `ModelRuntime`（认证、模型目录、OAuth 均不变），四个能力包经同一层门面挂载，因此 `customType`、`friend_*` 工具与斜杠命令的表现与 `pi` 后端一致。两者的差别在于：崩溃后可从检查点续跑、提交带请求标识去重、会话历史可版本化。

Durable 的存储独占只针对**写**：它的提交路径假定单写者且不做跨进程加锁。读不受影响——SQLite 的 WAL 模式支持多进程并发读，因此一个会话进程可以在对端仍在写入时读取对方的会话原文。只读读取会校验文件自身的 schema 版本，遇到更高版本的文件直接拒绝，而不是按旧结构误读。

## 6. 从源码构建

要求 macOS arm64、Node 24.15.0、npm 11.12.1。首轮需要网络，之后走已验证缓存；普通构建不跟踪 Pi main。

```sh
npm run bootstrap          # 取固定 Pi 源码、离线构建 tarball、写入本地依赖
node node_modules/electron/install.js
npm run build
npm run typecheck
npm test
npm start
npm run package:plugins    # 生成四个 .tgz 与解包目录
npm run package:mac        # 生成自包含 .app 与 zip
```

- `npm run bootstrap` 会 clone 锁定的 Pi SHA、校验 tarball 摘要、调用官方 `use-local-packages.mjs`；失败目录保留为 `.incomplete-*`，不覆盖已有缓存。`--verify-only` 只校验不联网构建。
- 交付打包前用 `--require-clean`（`node scripts/package-plugins.mjs --require-clean`）要求干净候选；应用摘要用 `sha256-tree-v1`。
- 离线测试 Provider 只在显式 `FRIEND_PI_TEST_PROVIDER=1` 时启用，界面标注「非真实服务」，其结果不代表真实模型质量。

## 7. 验证口径

项目区分四类证据，互不替代：源码测试 → 实际 SDK 进程 → 打包制品 → 真实 Computer Use 与真实模型。

- 历史记录（2026-10-17）：Memory P1–P4 批次全仓 1627 项通过，Memory 包 362 项、Topic & ReBuild 50 项、Memory Center UI 44 项，`tsc --noEmit` 0 错误；Swarm v2 平面另有 162 项与 15 项不变量 harness。当前提交未重跑全量，结论以重跑后的同一候选为准。
- 基准：Memory 九场景配对反事实（开 52/52、关 16/52 断言）、v3/v4→v5 迁移演练 40 项、Swarm v2 不变量 harness 15 项。
- 证据文件在 `.artifacts/qa/`，制品摘要在 `.artifacts/mac/delivery-manifest.json`，其中 `actualGUI` / `realModel` 等字段未运行时会保持 `NOT_RUN`。

历史记录不等于当前候选的验收；最终结论以同一候选上的提交、Pi SHA、制品摘要与实跑旅程为准。

## 8. 边界与未完成

**`durable` 执行后端（实验性，未完成）**：

- 已完成：会话运行、事件流、四个能力包挂载、`read`/`write`/`edit`/`bash` 工具、系统提示注入、工具与请求钩子、旧 JSONL 导入校验。以离线测试 Provider 驱动真实会话进程可跑到就绪并完成一轮。
- 未完成：GUI 全旅程验收、真实模型验收、跨会话来源引用的接线（只读读取器已完成并有测试，尚未接进来源引用路径）、swarm 成员仍运行在 `pi` 后端。
- 已知差异：`durable` 后端不挂载 MCP 扩展（本产品 MCP 服务器列表为空，实际无功能损失）；工具结果无 `structuredContent` 字段，依赖它的专家核对逻辑在该后端下不可用；无桌面托管时不做模型就绪校验，与 `pi` 后端一致。
- 切换前请确认会话历史可导入：导入校验发现丢弃项或重复 ID 时会拒绝切换，不会静默丢历史。

- Swarm 协作 v2 目前是 P0/P1：`integrate` 只记回执与门禁，不做物理文件应用；reviewer 的会话 ID 由调用方绑定；按尝试的预算预留/结算在后续阶段接入。
- 未实现：Swarm v2 的自动规划/仲裁/自动合并、worker 进程池、多团队、外部 provider、跨进程租约、A2A/MCP 导出、模板市场、配对真实模型质量评测。
- 侧栏「待审核」目前只反映当前会话的计划状态；后台会话里待批准的计划还不会投影进会话摘要。
- Swarm v2 工作台只展示控制器已返回的数据：快照不含裁决历史与全部尝试，`verify.list` 尚未实现，因此面板不能列出历史裁决；门禁校验需要手动填入候选摘要。
- Memory 不做向量检索与语义重排；基准是小样本确定性代理，不代表大规模语义质量。
- 「无限上下文」是保留约束、现场与可回查原文，模型窗口仍然有限。
- 工作树与审批是协作与授权边界，不是操作系统沙箱；Pi 仍采用高信任工具模型，关键破坏性操作要求确认。
- Git 面板只读/暂存/提交当前项目，不含 push、fetch、分支切换与冲突解决；提交绕过仓库钩子。
- 能力中心的「已加载」来自运行时清单；Pi 没有单独暴露扩展加载回执，因此该状态以会话可用列表为准。
- 本版本只交付本地源码与 macOS 应用：不创建远端、不发布 npm、不做证书签名发行或公证；ARM64 应用使用本地 ad-hoc 签名满足可执行要求，不具有发布身份。
