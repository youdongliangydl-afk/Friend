01 · 停止状态与显式恢复

既有能力修复 · 工作量M · 依赖 无 · 未来未实现

优化前

Swarm stop 在独立探针中 1ms 返回 stopped，但已启动的宿主检查约600ms后仍写入文件。成员终止、未知副作用接续已有实现，宿主检查未纳入取消链。另有错误提示可能回填旧提交的源码风险 CL-04，尚未真实 GUI 复现，不能算确认缺陷。

竞品对照与证据范围

Reasonix 本轮实际停止 ask 后显示‘本轮已中断’及检查工作区提示。MiniMax 公开 runtime 的 stop cascade 记录执行所有权和晚到唤醒抑制，是源码参考，桌面闭环本轮未确认。

优化方案

每次运行建立统一取消所有权，覆盖主会话、成员、检查及复核。停止按钮立即显示正在停止；收到进程/会话终止收据后才显示已停止。仍未终止的对象逐项列出，未知副作用保留检查现场和显式新尝试入口；错误恢复区分未提交草稿和已经成功提交的请求。

客户端变化

中央状态条与会话卡说明正在停止/已停止/未知；Swarm页仅在当前依赖图节点上标状态，取消收据与恢复细节从设置-任务诊断按需查看，不在工作台堆满检查卡。

预期使用体验

用户能判断什么已停、什么仍可能产生影响，不因绿色勾或回答结束误判。

实现边界

Swarm 控制器、SDK宿主进程生命周期与客户端；保持 Pi agent_settled 权威，不重写 loop。

完成判据

真实延迟检查在 stop 后不再产生第二次写入；覆盖取消中的成员、复核、进程崩溃、晚到事件和冷重启。不同会话的取消不能相互串扰。未知副作用不得自动重放。

风险与限制

停止不等于撤销已发生的外部效果；界面必须保留这一语义。

核验：SWARM-STOP-OBJECTIVE-CHECK；CL-04 待复现
真实截图：reasonix-stop-ask

02 · 原始历史缺失保护

既有能力修复 · 工作量S · 依赖 无 · 未来未实现

优化前

已登记 JSONL 文件缺失时 Main 传入 undefined，SDK 建立新历史，ready 后桌面索引静默改成新路径；隔离 Main harness 已复现。此时并未证明旧文件被删除，但原会话的历史入口会丢失。

竞品对照与证据范围

Codex 的 worktree 恢复和环境身份值得借鉴，但本轮自应用 GUI 被阻止；这是官方资料参考，没有直接体验历史损坏恢复。

优化方案

区分新建会话和恢复已有会话。恢复前验证已登记路径及会话身份；缺失/损坏时保留索引，显示明确错误和只读诊断。用户可重新定位原史、查看已有备份，或明确另建会话；禁止覆盖旧身份。

客户端变化

会话卡显示历史不可用；中央恢复卡保留项目/会话/原路径，提供选择原史与另建按钮。恢复失败仍可查看诊断并返回其他会话。

预期使用体验

历史异常可解释、可恢复，不把空白聊天伪装成原会话。

实现边界

Electron Main 的 session open 与索引；不把 SQLite 聊天副本引入系统。

完成判据

自有临时会话正常退出后移动 JSONL，打开必须报缺史且索引保持；恢复原文件后全部原条目和分支身份可读。另测损坏 JSONL、路径重定向和错误身份。

风险与限制

自动备份若新增，必须限定容量与可读权限；首修可以只实现 fail-closed 和手动重定位。

03 · 完整消息、Markdown 和工具过程

修复与展示完善 · 工作量M · 依赖 02 · 未来未实现

优化前

冷恢复只投影 role/text/id；原生 JSONL 的 image、thinking、toolCall 仍存在，但客户端缺工具名/参数/结果关联。当前流式本轮已有工具过程，不能说完全没有。链接、表格、编号列表按原 Markdown 显示，真实 GUI 与静态渲染都观察到。

竞品对照与证据范围

DSH 本轮普通 Chat 实际展开命令、输入、EXIT=0 和耗时，回答表格也正确展示；Reasonix 使用过程折叠与本轮结果收据。DSH 专门 Trajectory 视图本轮未切换，不能把普通工具展开记为 Trajectory 验收。

优化方案

从 Pi 原条目生成版本化展示 DTO，保留内容块、toolCallId、工具输入/输出/状态及来源。使用安全 Markdown 渲染链接、表格、编号、代码与复制，所有文件链接经过项目边界解析。历史和当前轮使用同一投影，不新增历史权威存储。

客户端变化

每轮默认显示简洁结果与折叠过程；展开后可核对工具名、命令、输入、输出与取消状态。图片原附件和能力限制可见；错误成为独立卡片。

预期使用体验

长对话重开后仍能验证‘读了什么、做了什么’，研发答复可直接阅读和打开来源。

实现边界

core history adapter、SDK事件DTO、Renderer；Pi JSONL仍唯一原史。

完成判据

同一真实原史含图片/思考/两个同名不同参数工具，冷重启前后投影一致，结果准确关联；安全链接、表格、列表、长代码、失败/取消工具与恶意HTML不能误执行。

风险与限制

渲染器要处理很大的工具输出，保留分页与原文入口，不能全量一次塞入DOM。

04 · 完整变更清单与未跟踪文件 Diff

既有能力修复 · 工作量S · 依赖 03 · 未来未实现

优化前

git diff HEAD 不包含未跟踪新文件。根 Agent 在临时项目新增 new-proof.txt，文件预览能打开，但 Diff 说‘当前没有工作区改动’；真实 Git fixture 也复现。

竞品对照与证据范围

Codex 官方 review 说明区分 Unstaged/Staged/Branch/Last turn，未提交审查包括未跟踪文件；仅资料核对。Reasonix 真实执行收据显示2文件、部分统计与检查结果；其 Diff 点击本轮未确认转变。

优化方案

用 Git status 建立完整文件清单，分别处理 tracked/untracked/deleted/renamed/binary。未跟踪文件显示内容作为新增，不偷偷 git add。第一步修漏报；再加入工作区与本轮变更两种范围和检查收据。

客户端变化

右侧按文件展示新增/修改/删除及跟踪状态，选文件看差异。本轮结果卡与真实检查联动，统计不可用明确提示。

预期使用体验

用户能审阅所有成果，避免以为没有改动而漏掉模型创建的新文件。

实现边界

桌面Git只读服务与结果投影；不新增提交/推送/PR自动流程。

完成判据

覆盖仅untracked、已暂存、未暂存、rename/delete、二进制、空文件、忽略文件与非Git项目；UI统计与真实status一致，查看不会改变索引。

风险与限制

本轮差异需有真实基线，不能把全工作区用户改动都标作Agent成果。

05 · 纠正约束与事实粒度的失效关系

既有能力修复 · 工作量L · 依赖 03 · 未来未实现

优化前

R01：普通纠正蓝色→绿色后现场仍保留双方，根 GUI 已再次复现。R02：同一消息中的数据库与UTF-8要求共用entry，只纠正数据库后整entry退休，未改的UTF-8约束一并丢失；此项为组合回归fixture，不冒充真实GUI已复现。

竞品对照与证据范围

Reasonix 精确版本源码将背景事实、指令、召回和冲突作用域分层；本轮只实际查看Memory页，未对其纠正做同等故障测试。DSH计划全文明确约束及成功标准，是当前任务可读性参考。

优化方案

把来源引用细化成事实/片段身份，保留原entry和被替代关系。普通明确纠正在下一安全边界处理；若无法可靠消歧，标记冲突待确认，不同时称两条为有效。Memory纠正只撤回相应事实和派生，其他约束继续有效。

客户端变化

工作台取消上下文页面。普通纠正必要时在对话里给一条简短冲突确认；事实替代、来源覆盖和派生影响在设置-高级诊断按需回查。

预期使用体验

改一条要求不会丢其他要求，也不会让旧要求继续以有效身份影响执行。

实现边界

Memory与ReBuild版本化失效事件、持久来源覆盖；不把Topic变成权限或执行控制。

完成判据

蓝→绿普通纠正安全边界后只绿有效；同entry两个事实只改一个，另一个和派生仍在；整理期间新增消息不丢；保存失败不推进水位。

风险与限制

语义识别不能只靠模型自评。无法确定的更正必须让用户确认，规则/来源仍能逐项核对。

核验：R01；R02

06 · 遗忘不复出、候选整理与中文明确记住

既有能力修复 · 工作量M · 依赖 05 · 未来未实现

优化前

真实Pi fork保留旧entryId/body、换新sessionId后，换词旧事实可再次成为候选；未自动active，不能说有效记忆已复活。‘请帮我记住’被规则误拒绝。Dream当前只精确去重与同标题冲突；真实GUI产生相近的数据库、UTF-8候选。

竞品对照与证据范围

MiniMax真实设置区分使用记忆与主动学习；Codex官方也区分use/generate，资料参考。Reasonix Memory页说明背景记忆引用前仍应验证；都不能代替本产品遗忘语义的测试。

优化方案

将遗忘绑定证据谱系和事实身份，跨fork/冷启动继续抑制；保留可回查原史。扩充中文肯定表达并严格保护否定。候选按事实聚合，冲突/重复/过期标记后由用户采用；Memory无Expert时保留方法候选，并提供恢复后补投。

客户端变化

工作台Memory只列本轮真实注入/采用的记忆与来源版本，候选/全库/纠正/遗忘/方法补投都在设置-记忆；所有类别有独立的生效说明。

预期使用体验

减少候选噪声，用户纠正和遗忘具有持续效果，常见中文记住请求可用。

实现边界

Memory谱系/抑制、Dream整理与跨插件补投协议；个人偏好仍仅明确要求保存。

完成判据

真实SessionManager.forkFrom及同会话冷启后换词反思不复出；短entryID碰撞不误删其他事实。‘请帮我记住’成功，‘请不要记住’与引用他人请求不保存个人偏好。

风险与限制

语义重复不应简单删除：保留证据、冲突及用户撤回权；从未验证的候选不能自动成为有效方法。

核验：M01；M03；Dream部分实现

07 · 应用级前台优先与后台工作中心

修复与管理完善 · 工作量M · 依赖 01 · 未来未实现

优化前

后台控制器彼此串行，但B会话开始前台请求只取消B实例，A后台provider仍继续。GUI只展示最近6项jobs，阶段与暂停入口已有。没有背景额度上限是已接受的产品选择，不应借竞品额外加入硬上限。

竞品对照与证据范围

Reasonix源码有跨会话任务监控，Codex官方支持长任务/后台worktree；本轮并未同等测试其前台抢占。这是可观察任务中心的参考，不是性能优越结论。

优化方案
