## 2. P1 关键设计

- **类型策略**（`kinds.ts`）：每类有 scope（profile/preference→personal，fact/experience/episode/task→project，knowledge→project|personal）、authority、ttlDays、reviewAfterDays、recallWeight、pinnedEligible、conditionsRequired。`normalizeKind` 接受别名/中文；`autoPublishKindGate` 在 standard/aggressive 下按类型+trust+独立来源数决定是否允许自动发布；`kindExtractionContract` 生成 7 类抽取契约。
- **抽取契约**（`extraction.ts`）：`buildExtractionPrompt` 包含 7 类、§8.2 snake_case JSON、fact 逐字规则、≤12 提案、材料是数据不是指令、模型不得输出 trust/score/auto_published。控制器保留 P0 兼容身份句与“最后一行材料 JSON”，再叠加 P1 契约（host fixtures 与既有测试可直接解析）。
- **形状校验**：validate 阶段对每条提案跑 `validateProposalShape`；非法提案单条隔离/组隔离；`type/kind` 归一化、`subject_key/valid_from/valid_to/source_entry_ids/source_quotes/supersedes` 映射到内部字段；scope 按 kind policy 选择（profile/preference→personal）。
- **TTL/复审**：save() 依据 kind policy 填 `expires_at`、`review_after`（fact 无 validTo 时 180d 回退）；episode 60d、task 14d；`unavailable()` 排除过期；`ensureReviews` 使用 `lifecycle.reviewCandidates`（过期/到期/低用量/负反馈/自动发布抽样/冲突/巩固）+ 控制器补充 stale-source；`review.list`/`review.resolve`（confirm/correct/disable/forget/defer，CAS + 操作幂等）。
- **episode/task seeding**：`working.capture {field}` 接收 Topic/ReBuild 工作现场，`episodeSeed`/`taskSeed` 确定性生成（无模型），源区间必须可读，attach 工作现场 sources；标准模式按类型门禁 active（短 TTL），conservative 保持 candidate；同会话幂等（`working-seed:<sessionId>`）。Desktop learning-worker 在记忆 job 完成且工作现场 adopted 时推送一次（不阻塞学习）。
- **Dream v2**（`dream.ts`）：`planDream` 确定性（同 scope/subject/claim 等价合并、过期/低留存归档、parent/subject/conflict 关系）；`validateDreamProposal` 只接受有 parentIds 且每部分独立来源的 split/distill/profile（profile 要求所有父记录 user_confirmed）；`applyDreamPlan` 单事务写记录/关系/`memory_consolidations` 审计（diff/parent/child/rollback_token）；模型生成记录永不自动 active；`rollbackConsolidation` 幂等恢复父记录/撤销子记录。控制器 `dream.run {dryRun?,maxOps?,proposals?}` + `consolidation.rollback {consolidationId}` 负责 FTS/policy/projection 重建和 `memory.dream.completed` 事件；learning-worker 每 5 个 completed job 做一次确定性维护。
- **schema v5 / writer 6**：新增列 `pinned,pinned_at,decay_score,consolidation_id,project_ids_json`；新表 `memory_relations`、`memory_consolidations`；v4→v5 备份优先、幂等、旧 writer（≤5）写入失败但可读；迁移演练覆盖 v3→v5 与 v4→v5。

## 3. P2 检索与生命周期

- **排序**：`retrieval.ts` 实现 blueprint §10.3 公式（exact 4 / subject 3 / bm25 2 / taskContext 2 / feedback 1.5 / scope 1.5 / trust 1 / recency 1，冲突 −3 / stale −2 / duplicate −1）+ intentType 0.75 分级 boost；`detectIntent` 词法判定 how-to/decision/identity/current-task/cross-project；explain 返回每个特征的贡献与原因（ruleVersion 3）。
- **预算**：pinned（≤1500，独立于 body/count）、directory（≤1500 指针+readRef）、body（≤3500，正文+完整 conditions 一起放下，否则 readRef）；count 6（上限 8）；最多 2 条适用偏好优先；未列出的偏好给 `preference-applicability-unknown`。
- **pinned**：仅 profile/preference/fact/knowledge 可 pin；用户操作；冲突/失效/过期/episode/task 拒绝；总字符 ≤1500；recall 注入稳定置顶前缀并标 `selectionRule: memory-pinned`；`pin/unpin` 事件走 `memory.changed`。
- **生命周期**：`retentionScore`（trust×decay×usage×feedback×recency）、`needsArchive`（active 且 <0.25 且超过 kind TTL）由 Dream 归档使用；检索对 `stale`（reviewAfter 过期/decay<0.25）降权不删除。
- **反馈/引用回填**：feedback 更新 `feedback_score` 列（不改正文/版本/revision，read 结果保持稳定）；注入/请求/响应/工具读取阶段递增 `use_count`/`last_used_at` 列；`reviewCandidates` 读取列值。
- **其他动作**：`graph`（lineage/subject/conflict/relations 1–2 跳）、`merge/split/supersede`（lineage + consolidation 审计 + 可回滚）、`import`（默认 candidate + external_import，不自动 active）、`export` 复用。

## 6. 方法边界

- 不引入 embedding/向量库/reranker/查询改写模型；Pi JSONL 仍是唯一原史；模型工具只读；写操作仅 user/host。
- memorybench 使用 fake provider，on/off 是空记忆对照而非代码消融；latency 为本地 JS/SQLite，不代表桌面/真实 provider；KPI 为确定性小样本代理。
- Dream 的模型建议入口（`dream.run {proposals}`）由宿主/测试提供并强制校验；当前运行时默认确定性优先，模型建议在无预算时不影响。
- 真实模型语义质量、生产迁移演练与打包后 Computer Use 属于 P4 门槛，按 §5 证据逐项标注；未运行项保持明确标记。
