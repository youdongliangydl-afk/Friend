## 2. 不变量覆盖（I1–I18）

| 不变量 | 实现/断言 |
|---|---|
| I1 成员状态机 | roster phase 只允许 provisioning→active\|failed、active→stopped；非法迁移拒绝 |
| I2 名字不可变/永久预留 | team 内 name/memberPath UNIQUE，failed/stopped 仍占位；immutable 字段校验 |
| I3 首条 prompt flush 后 admit | `admitMember` 要求 firstEntryPersisted=true |
| I4 task revision 连续 + CAS | 所有变更 expectedRevision；board 测试逐条覆盖 |
| I5 DAG 合法 | 存在/非删除/无自引/无重复/无环；ready 完整依赖 |
| I6 单任务一个 running attempt | 部分唯一索引 + claim 事务；调度重复调用不重复派发 |
| I7 写声明并发约束 | scopesOverlap/preflight/Held；独立写重叠拒绝 |
| I8 消息幂等/FIFO | messageId+信封幂等；per-target sequence；assertFifo |
| I9 interrupt 不清信箱/不释放 owner | P1 停止回执保留消息与现场（stop receipt + unknown 语义） |
| I10 wait 只观察调用后变化 | 基线 rowid 快照；10s–1h 校验 |
| I11 结构化裁决 | approved/findings/taskIds/resultVersions/candidateDigest/reviewedTip；自由文本不可提交 |
| I12 exact-tip | 裁决绑定 candidateTip；tip 变化拒绝（STALE_TIP），clean-rebase waive 需先有 stale 拒绝记录 |
| I13 返工上限/指纹 | task/graph 各 2 轮、失败指纹重复且无变更→暂停 |
| I14 unknown 不重放 | failAttempt(unknown) 暂停团队、任务 blocked、attempt unknown；不自动重放 |
| I15 逐对象停止回执 | terminated/unknown 明细，complete 仅当全部 terminated；unknown→团队 paused |
| I16 预算硬停 | used+reserved 超限/unknown/paused/deadline→BUDGET_EXHAUSTED，停止新派发 |
| I17 operationId 幂等 | v2 写动作复用 `swarm_action_receipts`；同 key 同意图返原回执，不同意图 VERSION_CONFLICT |
| I18 基线漂移门禁 | G08 targetBase/head、G14 workspace clean、G12 candidate/result versions；失败保留现场并 rejected |

20 条合并门禁 G01–G20 逐码实现并有 focused 测试；无封存通过的裁决时 `integrate` 只产生 rejected 回执，`silentMerge.assert` 恒为 0。

## 4. codex 交叉验收（gpt-6.1-sol）

模型 gpt-6.1-sol 对 v2 全部源码与 controller 路由做只读独立审查，提出 13 个 blocking + 1 个 non-blocking 问题；合入前全部修复或明确记录边界：

| 类别 | 审查发现 | 处理 |
|---|---|---|
| 作用域 | v2 路由未把 team/task/member 绑定到当前 project/session，可跨会话读写 | controller 传入 projectId/sessionId/projectDir；`bindScope` 对所有动作解析并校验 team.projectId/rootSessionId，team.create 强制覆盖为当前作用域；e2e 增加跨项目/跨会话拒绝用例 |
| 状态机 | `task.transition` 可绕过交付/验证/整合直接 deliver→verify→complete | service 拒绝 claim/admit/deliver/verify/complete/retry 原始迁移，必须走 scheduler/attempt.complete/verify.apply/integrate；silent merge 断言基于 applied receipts |
| 返工 | rework 断开会话但未终止运行中 attempt，导致无法准备新 attempt | startRework 先把受影响任务的活动 attempt 标 failed/interrupted、释放写声明、清 currentAttemptId；新增测试覆盖再次调度成功 |
| 日志 | update 事件只记字段名不记值 | team.updated/task.updated 写入有界真实 values（字符串 2000/数组 64/对象深度 3） |
| 写声明 | `src/./a` 可绕过 `src/a` 重叠检测；claim 接受任务外 scope | normalizeScope 折叠 `.` 段；scope 由任务板写入并校验，claim 仅消费任务声明 |
| 预算 | 调度用合成 attemptId 预留 0 用量、吞错可留下部分预留、未接成员预算 | service 在派发前 `assertTeamBudget` + 任务预算检查；不再写合成预留；按 attempt 的 native receipt 结算/成员预算留给 P1.1 并在 README 边界注明 |
| 复核 | 省略 sessionId 可绕过复核独立性；write 任务空 candidateTip 可通过 exact-tip | submitVerdict 强制非空 session 且不得等于 attempt/author session；write 任务空 tip 拒绝封存 |
| 契约 | applyVerdict 未比较冻结 contract digest；G19 接受共享 checkId 的他处证据 | applyVerdict 重算 contractDigest，变化→stale；G19 要求证据行属于本任务，且 check.evidenceRef 存在时精确匹配 evidence_id |
| 门禁 | gateInput 可覆盖 taskId/candidateDigest；changedPaths:[] 可隐瞒越界文件 | integrateTask 只从允许字段构建 gateInput、内部绑定身份、changedPaths = 调用值 ∪ files 路径并全量校验 |
| 应用 | v2 集成写 receipt 但不执行真实文件系统应用 | 明确边界：P0/P1 记录逐文件回执与门禁，真实文件应用仍由既有 swarm 隔离/应用平面执行；v2 不宣称已落盘，README 与验收边界同步说明 |
| 消息 | 投递可跳过更早队列消息；跨目标 cursor 可永久跳过 | deliver 强制同目标 FIFO；list/wait 在 afterSequence>0 时要求 targetId；service 转发 targetId |
| 调度 | provisioning/stopped 成员可派发；generation 硬编码 0 | scheduler 要求 member.phase==='active' 并使用成员真实 generation |
| 预算幂等 | unknown settle 重试报冲突 | 同意图 settle 幂等返回，不同值/意图仍冲突 |
| 演练 | 不变量 harness 把失败观察当 PASS、预算耗尽在整合前污染门禁 | harness 重写为每项必须断言预期结果；预算用例独立 fixture；主任务先完成 applied receipt 再断言 silent merge=0 |

第二轮只读复验（同一 gpt-6.1-sol）对新修复做了对抗性检查，又指出 15 项待办并已继续修复：controller 绑定对象的跨团队校验、read-only 任务完成后进入 done（不再卡依赖）、block/cancel 终止活动 attempt、返工释放历史 claim 并允许替换应用回执、verdict 跨任务拒绝、契约变更后禁止整合、`src/../secret` 路径归一化、G19 只接受 passed 且绑定本任务 attempt 的证据、V3 第二复核会话去重、acquireClaim 只能声明任务内 scope、单任务预算耗尽不再阻塞全团队、incorporate FIFO、静默合并计数只统计 applied、harness 增加 FIFO/G08 具体断言。

仍明确记录的 P0/P1 边界（非隐瞒）：
- v2 `integrate` 记录逐文件回执/门禁/审计，不执行物理文件应用；真实应用/回滚由既有 swarm 隔离与应用平面完成（见 §5）。
- reviewer 的 sessionId 由调用方提供并做唯一性校验；在 P0/P1 controller 边界校验其非空、不同于 attempt/author、V3 复核之间不同；宿主 UI 尚未把原生会话 ID 绑到该字段（P2 工作台接线）。
- 每 attempt 的预算预留/结算（native receipt 关联）在 P1.1 与成员运行时接线；当前 P0/P1 在派发前做团队/任务硬门禁。
- P2/P3/P4（自动规划/仲裁/自动合并、工作台 UI、worker 池/外部 provider、A2A、真实模型配对评测）不在本次范围。

复验：v2 测试 162/162、harness 15/15、tsc 0；全仓测试在最终提交前重跑（见 §3）。审查未再发现嵌套事务误用或 writer fence 绕过。

## 5. 安全与权限边界

- 协作状态唯一写入口是 `CoordinationService`（controller `v2.*`）；模型工具本阶段不新增 v2 工具，避免模型自批准；reviewer/verifier 角色与 attempt 作者独立性由 `submitVerdict` 强制。
- 命令检查不执行命令，只消费调用方提供的 exit code/输出，防止「检查即执行」越过审批；不可逆动作要求 user/host origin。
- **应用边界**：v2 `integrate` 在 P0/P1 只记录逐文件回执、门禁结果与审计事件，不直接写文件系统；真实文件应用/回滚由既有 swarm 隔离/应用平面（worktree/staging、逐文件 receipt）执行。因此 v2 的「applied」是协作账本状态，不宣称物理落盘；两者由候选 digest/基线绑定。
- `swarm_v2_*` 表 writer fence 5：旧 writer 只读；迁移前 `VACUUM INTO swarm-pre-v2-*.sqlite`；不重写既有 documents/图记录。
- unknown 副作用只暂停与保留现场，禁止自动重放；预算 unknown 不归还为已知。
