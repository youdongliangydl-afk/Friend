# 会话全屏工作台

- 全屏属于当前会话的布局设置；顶栏的还原按钮回到普通工作台，不进入 macOS 系统全屏。
- 顶部项目名称全部收起，包括临时会话。左侧文件夹图标展开项目抽屉；当前项目的会话栏可单独收起。
- 会话是固定标签，工具页各为单例，网页可有多个标签。加号打开网址和工具入口；重复选择工具会切到原标签。
- 工具页的浮动输入框共享当前会话草稿、附件和发送设置；底部仅保留加号与发送/停止。模型、协作、计划等完整控制位于会话页。
- 新回复与待审批状态通过浮动区提示，点击返回会话处理。
- 常规设置可指定新会话默认布局和浏览器登录范围。默认值只用于新会话，不覆盖已有会话。
- 会话菜单可选浏览器登录范围：整个 Friend 共用、按项目隔离、按会话隔离。更改已有网页的范围需确认重新加载；旧分区登录数据保留，不复制到新分区。
- 浏览器支持 HTTP/HTTPS 网址、导航、刷新、上传、下载及网页弹窗。关闭来源标签时保留尚在下载的宿主，传输结束后清理。下载进度保留到本次应用退出；重启不自动重试下载。
- 布局、标签与网页网址跨重启恢复；浏览器内存中的表单、导航栈和脚本生成的空白弹窗正文不跨重启恢复。终端仍遵循原有不重放命令规则。

## 实现边界

`SessionViewState` 是版本 1 的桌面界面状态，存于 desktop RecordStore 的 `session-ui:<desktop session ID>` 键，与 Pi JSONL 分离。普通布局页和终端开关作为还原快照保存；首次恢复完成后才允许写回，防止旧会话状态覆盖新会话。

主进程提供 `session.ui.get/update`、`browser.list/present/navigate/action/cancelDownload` 和 `composer.sync`。界面状态更新可以在执行中完成，不改变执行目标、模型、权限或 Pi 消息历史。会话删除同时清理其界面记录与页面实例；共用浏览器分区不因此清空。

BrowserHost 管理 WebContentsView。访客与弹窗强制关闭 Node，开启隔离、sandbox 和 webSecurity，不加载 Friend preload；持久分区由 app、工作目录摘要或会话 ID 决定。弹窗采用 Electron 返回的 WebContents 以保留 opener；页面自行关闭会清理其标签。所有 Friend IPC 仍验证主窗口的主 frame。浮动输入框使用独立的可信本地视图与专用、受 token/session/epoch 约束的消息通道，发送仍由 App 的原控制器执行。

原生网页与 DOM 不能靠 z-index 互相覆盖。页面与输入层分别计算 bounds，并跟随窗口缩放；设置和审批打开时隐藏网页层。会话切换由主进程统一隐藏旧原生视图，之后按新会话恢复。工作台与终端保持原控制器、文件缓存和进程管理。
